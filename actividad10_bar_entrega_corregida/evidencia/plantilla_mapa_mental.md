# Plantilla para mapa mental o notas técnicas

## Tema central

Errores frecuentes en HTML y CSS: diagnóstico, corrección y documentación

## Rama 1. Errores en HTML

- Rutas mal escritas en enlaces, imágenes o scripts.
- Etiquetas mal cerradas o mal anidadas.
- Ids o clases que no coinciden con CSS o JavaScript.

## Rama 2. Errores en CSS

- Propiedades mal escritas, como `max-wdith`.
- Valores inválidos, como `display: grips`.
- Variables inexistentes, como `--dorado`.

## Rama 3. Errores en JavaScript

- Cadenas de texto sin cerrar.
- Funciones llamadas con nombres incorrectos.
- Búsqueda de elementos con ids que no existen en el HTML.

## Rama 4. Herramientas de diagnóstico

- Consola del navegador: muestra errores de JavaScript.
- Inspector: permite revisar HTML y estilos CSS.
- Network / Red: muestra archivos que no cargan.
- VS Code: permite revisar rutas, nombres, clases y estructura.

## Rama 5. Proceso de corrección

1. Abrir el proyecto y observar qué falla.
2. Revisar consola, inspector y Network.
3. Identificar el archivo afectado.
4. Corregir un error a la vez.
5. Guardar, recargar y comprobar que funcione.

## Rama 6. Buenas prácticas

- Usar nombres claros y consistentes.
- Revisar rutas de archivos.
- Probar cada sección después de corregir.
- Documentar los errores encontrados.
- Usar la consola desde el inicio.

## Reflexión final

Aprendí que muchos errores web aparecen por detalles pequeños, como una letra mal escrita o una ruta incorrecta. También entendí que la consola, el inspector y Network son herramientas muy útiles para encontrar el origen de un problema. Corregir paso a paso ayuda a no confundirse y permite comprobar que cada solución realmente funciona.
